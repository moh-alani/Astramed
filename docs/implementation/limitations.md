# Limits and unfinished release work

ASTRAMED is an unvalidated demonstration, not a production medical device. Monitoring cutoffs are illustrative except the explicitly pinned NASA reference comparisons. Individual mission certification, risk assessment and clinical review have not occurred. “Nominal” is not a medical safety judgement, especially for oxygen, blood pressure, activity and strength, which have no clinical alarm rule here.

The five-trial browser task is not a clinical PVT. Hardware and browser latency are not calibrated. No physiological causal inference, diagnosis, medication, health score or model confidence estimate is generated. Seeded baselines have illustrative observation counts; actual preflight raw samples and calibrated reference intervals do not exist.

NASA references pin reviewed versions. The standard landing page also advertises a newer Volume 2 download; this app retains the specification’s Rev D reference as confirmed by NASA’s technical brief and does not assert it is the latest requirement. The original older PDF URL returned 404. Off-nominal procedures and emergency treatment are not implemented. No live environmental sensor, real dosimeter, wearable or NASA experimental dataset is integrated.

All four identities are freely selectable for judging; the Crew display demonstrates information minimization without implementing secure medical access control. State is local to one browser. Exported JSON includes all fictional identities’ local records. Enter only demonstration readings. There is no external emergency notification or ground communication system.

Voice synthesis depends on browser/OS availability and may require network access. Offline speech has not been tested. The worker only caches after a successful production load; first-load offline availability is impossible without prior installation. Browser cache eviction, private-mode restrictions and local storage loss can remove state/assets. Production caching was tested in automated Chrome; other target browsers and installed PWA behavior require validation.

Basic accessibility automation is not a full accessibility audit or clinical human-factors evaluation. Testing on flight hardware, small touch targets under operational constraints, assistive technologies and multiple browsers remains future work. Exercise demonstrations require an actual approved mission plan.

The approved source is published in the separate astramed-prototype repository and deployed with GitHub Pages. The existing astramed site and local template copy are preserved. See the validation record for observed publication status. No official recorded video, final slide artifact, competition portal submission or deadline verification is included. Submission planning documents and static deployment instructions are provided. Final event rules should be checked by the team before submission.
